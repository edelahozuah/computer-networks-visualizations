Browser cache: cache or server?

Model assumptions
  • Every 200 OK response carries Last-Modified and its explicit freshness: Cache-Control: max-age=N (fresh for N seconds from the moment it was received), no-cache (stored, but always revalidated) or no-store (not stored). A response without freshness information is not stored either.
  • An object that is not in the cache is requested with a normal GET and answered with 200 OK.
  • A fresh copy (age < max-age) is served from the cache without any message.
  • A stale copy (age ≥ max-age, or no-cache) is revalidated with a conditional GET: If-Modified-Since equal to the Last-Modified of the copy. The server answers 304 Not Modified without a body if the object has not changed (the copy becomes fresh again for another max-age), or 200 OK with the new object if it has.
  • The page is one more object: if it is fresh or revalidated with 304, the browser knows the embedded objects from the cached copy. Within a visit the page is handled first and then the objects in order, over a persistent connection without pipelining.
  • Last-Modified is shown symbolically as “L·version”; each change on the server increases the version. Visits are instantaneous: the model says which messages are sent, not how long they take. Out of scope: ETag, heuristic freshness, proxies.
