Supuestos del modelo
  • Un único enlace de velocidad R y retardo de propagación d_prop entre cliente y servidor; sin otro tráfico, sin pérdidas y sin control de congestión TCP (sin arranque lento).
  • Las peticiones (GET) y los segmentos de control TCP tienen tamaño despreciable: tardan d_prop en llegar y no tienen tiempo de transmisión.
  • Cada objeto (y el HTML) se envía como un bloque de L bits: X = L/R. Se desprecian las cabeceras.
  • Se desprecia el procesamiento en el navegador; el servidor necesita t_proc para preparar cada respuesta.
  • Sin canalización, el cliente envía la petición del objeto i cuando llega el último bit del objeto i−1.
  • Con canalización, el cliente envía las N peticiones a la vez; el servidor las responde en el mismo orden, una tras otra. En el diagrama las peticiones se dibujan ligeramente separadas solo para distinguirlas.
